# Design: 条款批量上传进度与重新上传语义

**日期**: 2026-05-26  
**状态**: 已确认

## 概述

本设计在现有 `chapter_batch` 工作台基础上，补足两类能力：

1. 已上传成功的条款支持右键 `重新上传`
2. 批量上传工作台提供真实、可解释的运行进度

这次设计不是新增一个独立上传模块，而是在现有 `chapter_batch` 的 `repository / service / executor / view / drawer` 结构上重整上传语义、条款状态语义和进度事件流，使其符合当前已确认的业务要求。

## 已确认约束

### 重新上传

- 仅对 `上传成功` 条款开放右键 `重新上传`
- 必须复用现有 `chapterId`
- 直接把当前本地 `source_docx_path` 重新上传到已有条款
- 不再做重复检查
- 不重新创建 chapter
- 成功后状态保持 `上传成功`
- 失败后状态变为 `上传失败`

### 重复命中后的用户决策

- 取消 `重复跳过` 作为长期稳定状态
- 当用户不选择覆盖时，条款恢复到本次上传开始前的原状态
- 原来是 `上传成功` 就保持 `上传成功`
- 原来是 `待上传` 就保持 `待上传`
- 原来是 `上传失败` 就保持 `上传失败`

### 重复弹窗按钮

重复弹窗不再使用 `Yes / No / Cancel`。按钮固定为业务按钮：

- `覆盖`
- `跳过当前条款`
- `后续重复全部跳过`

其中 `后续重复全部跳过` 的作用域只限 **当前文档剩余条款**，不影响本批其他文档。

### 进度视图

- 文档列表中 **不要新增“真实进度”列**
- 进度环形图直接显示在 **状态单元格** 中
- 抽屉内部保持当前方向，只补足当前文档的上传进度展示

### 处理阶段口径

- `预处理 + 拆分` 合并为一个阶段，统一显示为 `处理中`
- `处理中` 是一个 0-100% 的完整进度
- 上传阶段单独显示为 `上传中` 的 0-100%

### 导入即显示

- 文档一旦导入，列表中要立即出现记录
- 不能再等预处理和拆分结束后才显示
- 初始状态直接是 `处理中`

## 目标

- 让用户在文档导入后立即看到工作台记录和当前阶段
- 让列表状态具有“可解释的实时进度”，但不增加新的进度列
- 让 `上传成功` 条款支持低摩擦覆盖上传
- 让重复命中后的行为不污染条款稳定状态
- 保持抽屉的单文档核对体验不被复杂状态机破坏

## 非目标

- 不修改 splitter 的拆分规则和清洗效果
- 不引入新的后端接口
- 不在本轮把上传事件持久化成完整审计日志
- 不把抽屉改造成新的多文档工作台

## 用户界面设计

## 文档列表

### 列表行即时出现

用户导入文件或文件夹后，工作台先同步创建本地文档记录并刷新列表，再启动后台 `预处理 -> 拆分`。

因此用户会立刻看到新行：

- 状态：`处理中`
- 进度：状态格内的环形图，初始为 `0%`

### 状态单元格

状态单元格成为进度承载位，不新增单独的进度列。状态格展示规则如下：

- 运行态：
  - `处理中` + 环形图 + 百分比
  - `上传中` + 环形图 + 百分比
- 稳定态：
  - `待确认`
  - `待上传`
  - `已完成`
  - `部分完成`
  - `失败`

稳定态不显示环形图，只显示状态文字。

### 环形图样式

- 使用小型紧凑环形图，适合嵌入状态格
- 文字与环形图共处一个状态单元格
- 百分比可以显示在环形内或状态文字下方，但不能扩展成单独列

## 抽屉

抽屉保持当前单文档核对和上传语义，不新增过多信息层级。

本轮只要求：

- 在上传过程中显示当前文档上传进度
- 显示当前第几条 / 总条数
- 可显示当前条款号和当前动作

抽屉不承担全局进度聚合职责。

## 重复弹窗

重复命中时使用自定义业务弹窗，而不是 `QMessageBox.question`。

弹窗至少展示：

- 条款号
- 测试内容
- 具体产品
- 归属文件夹

弹窗按钮固定为：

- `覆盖`
- `跳过当前条款`
- `后续重复全部跳过`

行为定义：

### 覆盖

- 复用已有 `chapterId`
- 直接上传当前本地 docx
- 不重新创建 chapter
- 不同步修改后端既有条款字段

### 跳过当前条款

- 当前条款本次不上传
- 恢复为进入本次上传前的原状态
- 当前文档后续条款继续执行

### 后续重复全部跳过

- 对当前文档剩余条款生效
- 后续若再次命中重复，不再弹窗
- 这些命中的重复条款全部恢复原状态并跳过上传
- 未命中重复的条款仍继续正常上传

## 状态模型

## 文档状态

文档稳定状态保留为：

- `处理中`
- `待确认`
- `待上传`
- `上传中`
- `已完成`
- `部分完成`
- `失败`

说明：

- `处理中` 表示 `预处理 + 拆分` 合并后的运行阶段
- `上传中` 表示条款创建与文档上传阶段

## 条款状态

条款稳定状态收敛为：

- `待上传`
- `上传中`
- `上传成功`
- `上传失败`

删除 `重复跳过` 作为长期稳定状态。

## 临时重复字段

允许保留以下字段作为辅助信息：

- `duplicate_flag`
- `duplicate_reason`
- `user_decision`

它们只表达“最近一次上传前检查或决策结果”，不再驱动条款稳定状态和文档稳定状态聚合。

## 进度模型

## 处理中进度

`处理中` 是合并后的一个 100%：

- 前半段来自预处理真实进度
- 后半段来自拆分真实进度

但对用户只显示一个统一状态：`处理中`

用户不会看到“预处理中”和“拆分中”两个独立进度态。

## 上传中进度

`上传中` 是当前文档上传阶段的一个 100%。

进度由“当前文档已处理条款数 / 需处理条款总数”驱动。

条款级处理顺序为：

1. 重复检查
2. 创建 chapter（若需要）
3. 上传 docx

只要当前条款进入这套处理链路，就应推进本次上传进度。

## 事件模型

建议为 `chapter_batch` 增加轻量运行时进度事件，不引入新的后端契约。

### 文档处理进度事件

- `phase = processing`
- 表示 `预处理 + 拆分` 的合成进度
- 事件字段至少包括：
  - `document_id`
  - `phase`
  - `percent`
  - `message`

### 文档上传进度事件

- `phase = uploading`
- 表示当前文档上传进度
- 事件字段至少包括：
  - `document_id`
  - `phase`
  - `percent`
  - `current_index`
  - `total_count`
  - `current_clause_term`
  - `action`（如 `duplicate_check / create / upload`）
  - `message`

本轮事件可以只通过 `worker signal -> view` 传递，不要求写入数据库事件表。

## 行为语义

## 导入链路

导入行为改为：

1. 立即创建本地文档记录
2. 立即刷新列表，显示 `处理中 0%`
3. 后台启动预处理与拆分
4. 完成后进入 `待确认` 或 `待上传`

## 重新上传

对 `上传成功` 条款：

1. 右键选择 `重新上传`
2. 跳过重复检查
3. 直接用现有 `chapterId` 调用上传接口
4. 成功保持 `上传成功`
5. 失败改为 `上传失败`

## 重复命中但不覆盖

条款在进入一次上传尝试前，执行上下文中需要保存“进入前原状态”。

当用户选择：

- `跳过当前条款`
- `后续重复全部跳过`

则命中的当前条款或后续重复条款全部恢复原状态，而不是落成新的稳定态。

## 聚合规则

文档状态聚合只依赖条款真实稳定状态：

- `上传成功`
- `上传失败`
- `待上传`
- `上传中`

重复命中但未覆盖不会改变条款稳定状态，因此也不应额外制造新的文档状态。

## 代码落点

### `src/tuv_tools/core/chapter_batch/models.py`

- 重整文档状态枚举
- 重整条款状态枚举
- 删除 `重复跳过` 稳定态语义

### `src/tuv_tools/core/chapter_batch/repository.py`

- 调整文档聚合规则
- 去掉对 `重复跳过` 的稳定聚合依赖

### `src/tuv_tools/core/chapter_batch/executor.py`

- 增加上传进度回调
- 支持 `上传成功` 条款直接重新上传
- 支持“重复命中但恢复原状态”的执行语义
- 支持当前文档范围的“后续重复全部跳过”

### `src/tuv_tools/ui/views/chapter_batch_view.py`

- 文档导入后立即落记录并刷新列表
- 状态格嵌入环形进度视图
- 接收处理阶段与上传阶段进度事件
- 替换旧的重复确认交互

### `src/tuv_tools/ui/widgets/chapter_batch_clause_table.py`

- `上传成功` 条款增加右键 `重新上传`
- 移除围绕 `重复跳过` 的菜单分支

### `src/tuv_tools/ui/widgets/chapter_batch_drawer.py`

- 保持当前抽屉布局
- 补足当前文档上传中进度信息展示

## 手工验证

1. 导入文档后，列表立即出现新记录
2. `处理中` 环形图从 0% 到 100%
3. 完成后状态切到 `待确认` 或 `待上传`，环形图消失
4. 上传时状态格显示 `上传中` 环形图
5. `上传成功` 条款右键可 `重新上传`
6. 重复命中后弹窗按钮为 `覆盖 / 跳过当前条款 / 后续重复全部跳过`
7. 选择不覆盖后，条款恢复原状态
8. 抽屉中当前文档上传进度可见

## 风险与约束

- 现有代码和测试中大量使用 `重复跳过`，本轮重整会波及 `models / repository / executor / view / tests`
- `处理中` 是 UI 合成状态，不代表底层只有一个 worker 阶段，因此需要显式的进度映射层
- 环形图放入状态格后，列表刷新要避免高频 repaint 导致 UI 抖动，建议沿用节流思路

## 验收标准

- 用户导入文档后，无论预处理和拆分是否完成，列表立即出现记录
- 文档列表无独立进度列，进度环形图只出现在状态格
- `处理中` 合并表示预处理和拆分的一个 100%
- `上传中` 表示上传阶段的一个 100%
- `上传成功` 条款可右键 `重新上传`
- 重复命中不再把条款稳定状态落为 `重复跳过`
- 用户不覆盖时，条款恢复本次上传前原状态
- 抽屉中上传进度可读且不额外复杂化现有布局
