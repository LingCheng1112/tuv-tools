# Design: Chapter Batch Import Workspace

**日期**: 2026-05-24  
**状态**: 待审阅

## 概述

本设计定义一个新的桌面端独立页面，用于把现有的文档导入/预处理/拆分能力，与现有的条款目录树查询、条款创建、Chapter 文档上传能力串成一条完整流程。

这个新模块不是一次性向导，而是一个长期可用的**文档工作台**：

- 每个导入文档都是独立记录
- 支持批量导入、批量确认、批量执行
- 结果和失败项会被持久化保存
- 应用重启后仍可回来继续查看、继续处理、继续重试

模块目标是帮助用户完成以下连续动作：

1. 导入 DOCX 文档
2. 选择拆分模式并自动执行拆分
3. 生成待创建条款草案
4. 在确认抽屉中校对文档级公共字段与条款级差异字段
5. 批量创建 Chapter
6. 使用 Chapter ID 调用 `POST /api/chapter-doc/import` 上传对应 docx
7. 在工作台内持续查看、恢复、编辑、重试结果

## 总体方案

推荐方案为：

**单列表工作台 + 双击打开右侧抽屉 + 顶部标签批量确认**

核心特点：

- 新模块是侧边栏独立页面
- 主页面始终是单列表文档工作台
- 双击文档后，从右侧滑出抽屉
- 单文档确认时，抽屉显示一个文档
- 多文档确认时，抽屉顶部出现标签页，按当前列表显示顺序切换多个文档
- 确认保存后，弹窗询问“直接上传”还是“稍后处理”

## 目标

### 功能目标

- 新增一个独立页面，完整覆盖“导入、拆分、确认、创建、上传、结果恢复”的业务链路
- 支持两种拆分模式：
  - `章节`
  - `条款`
- 批量导入时统一选择一次拆分模式，并自动对本次导入文档执行拆分
- 后续允许单个文档单独修改拆分模式并重新拆分
- 自动识别标准号，如 `60335-2-9`
- 基于标准号和目录树自动推导目标 `folder.id`
- 在确认抽屉中提供目录树下拉选择器，允许用户手动修正目标目录
- 批量创建 Chapter 后，自动调用 `POST /api/chapter-doc/import` 上传对应文档
- 结果项持久化保存，支持失败恢复和条款级重试

### 非目标

- 不替代现有“文档拆分”页与“条款管理”页
- 不复用现有拆分页的 `imported_documents`
- 不改造后端目录树模型
- 不新增“大版本条款测试内容字典表”
- 不自动删除后端已创建 Chapter 或已上传文档
- 不自动重新生成已拆分 docx 的内容
- 首版不支持直接打开 OnlyOffice 在线文档

## 页面结构设计

### 1. 主页面

主页面是单列表工作台，文档为独立记录。

#### 顶部工具区

- `导入文件`
- `导入文件夹`
- `批量确认`
- `开始执行`

说明：

- `开始执行` 只作用于当前选中的文档
- 不扫描当前筛选结果里的所有待处理文档

#### 顶部筛选区

- 搜索文档名 / 标准
- 状态筛选
- 模式筛选
- 显示全部 / 指定状态

说明：

- 状态筛选位于筛选区，不放在 `开始执行` 按钮旁边

#### 列表字段

建议长期显示：

- 选择框
- 文档名
- 标准
- 模式：`章节` / `条款`
- 文档状态
- 条款结果摘要
- 更新时间

说明：

- 列表中不显示“操作提示”文案

### 2. 抽屉交互

- 双击文档后，才从右侧滑出抽屉
- 单文档时，抽屉只显示一个文档
- 多文档批量确认时，抽屉顶部出现标签页
- 标签页按**文档当前列表显示顺序**排列

#### 抽屉结构

自上而下建议固定为四个区块：

1. 文档头部
2. 文档级操作区
3. 文档级公共字段区
4. 条款明细区

#### 文档头部

- 文档名
- 当前文档状态
- 当前模式：`章节` / `条款`
- 标准号
- 条款结果摘要

#### 文档级操作区

至少包括：

- `保存确认`
- `直接上传`
- `稍后处理`
- `重新拆分`

根据状态补充：

- `开始执行`
- `取消执行`
- `删除记录`

#### 文档级公共字段区

- `标准`
- `归属文件夹`
- `产品类别`
- `PlanSR`
- `标准版本`
- `条款版本`
- `具体产品`

- `chapter ID`
- 重复标记
- 错误信息

## 拆分模式与导入流程

### 1. 模式命名

界面统一使用：

- `章节`
- `条款`

不显示“模式”二字作为值本身。

### 2. 批量导入时的模式选择

- 用户在本次批量导入完成后，统一选择一次拆分模式
- 本次导入的所有文档先按同一种模式自动执行拆分

### 3. 后续单文档修改模式

- 只允许针对单个文档做模式调整
- 触发后执行“重新拆分”

### 4. 重新拆分规则

重新拆分前必须弹确认框，明确说明：

- 只会重置本模块中的本地记录数据
- 不会删除本地原始文件
- 不会删除后端已创建的条款
- 不会删除已上传文档

重新拆分行为：

- 保留文档主记录
- 删除该文档当前全部本地条款记录
- 按新模式重新生成条款草案
- 清空该文档当前本地执行结果
- 文档状态回到 `待确认`

## 业务规则

### 1. 文档与目录归属

- 一个源文档拆出来的全部条款，共享同一个目标 `folder.id`
- 这个 `folder.id` 应对应原文档标准号所在的版本号目录
- 例如标准号为 `60335-2-9`，则该文档拆出的全部条款都应归到 `60335-2-9` 目录

### 2. 标准号识别失败

如果未识别出标准号：

- 文档仍进入确认阶段
- `标准` 先留空
- 用户可手动填写 `标准`
- 用户可手动选择 `归属文件夹`
- 用户也可以放弃该文档本次拆分上传任务

### 3. 条款字段默认值

确认表中每条待创建 Chapter 的默认映射如下：

- `term`
  - `章节` 模式：章节号，如 `10`
  - `条款` 模式：条款号，如 `10.1`
- `testContent`
  - `章节` 模式：标准号占位
  - `条款` 模式：识别结果；识别不到则显式空值占位
- `productType`
  - 优先由目标版本号目录的上级目录推导
  - 推导失败则默认 `家电`
- `planSr`
  - 固定 `1`
- `standard`
  - 文档识别出的标准号
- `standardVersion`
  - 默认空
- `version`
  - 固定 `1.0`
- `folder.id`
  - 由最终确认的目录树目标节点决定
- `specificProduct`
  - 默认空

### 4. 可编辑范围

确认阶段和结果阶段，表单只是帮助用户批量预填，所有相关参数都允许修改。

文档级公共字段：

- `标准`
- `归属文件夹`
- `产品类别`
- `PlanSR`
- `标准版本`
- `条款版本`
- `具体产品`

条款级差异字段：

- `条款编号`
- `测试内容`

### 5. 表单编辑与 docx 内容解耦

如果用户在确认页或结果页里修改了：

- `条款编号`
- `测试内容`

则：

- 不自动重生成本地拆分 docx
- 后续上传仍然沿用原先拆分出的 docx 文件

## 目录树匹配与目录树选择器

### 1. 自动匹配目标

系统最终需要确定的不是“一个标准号字符串”，而是“一个最终目录节点”，该节点的 `id` 作为所有待创建 Chapter 的 `folder.id`。

### 2. 自动匹配规则

自动匹配时遵循以下顺序：

1. 在条款目录树中查找目录名与标准号完全相等的节点
2. 若唯一命中，则直接设为默认目标目录
3. 若命中 0 个或多个，则视为“未唯一匹配”

### 3. 未唯一匹配时的处理

若目录未唯一匹配：

- 文档仍可进入确认页
- 在确认抽屉中显式提示“目录未唯一匹配，请手动选择目标目录”
- 用户必须在确认保存前手动选定目标目录

### 4. 可复用目录树选择器组件

建议抽出一个可复用组件：

**条款目录树选择器**

职责：

- 展示条款目录树
- 支持懒加载子节点
- 支持按目录名搜索
- 支持选中最终 `folder.id`
- 支持回填当前选中的目录名称

复用场景：

- 新模块确认抽屉中的 `归属文件夹`
- 现有条款管理里的手动新增条款
- 结果页里失败条款重新编辑时的目录选择

说明：

- 目录树选择器只负责“选目录”
- 标准号自动匹配逻辑单独存在，二者不耦合

## 确认流程

### 1. 单文档确认

- 双击某个 `待确认` 文档
- 打开抽屉
- 编辑公共字段与条款明细
- 点击 `保存确认`

### 2. 多文档批量确认

- 用户选中多个 `待确认` 文档
- 触发 `批量确认`
- 打开同一个右侧抽屉
- 顶部以标签页切换多个文档
- 每个文档使用相同的确认结构

### 3. 保存确认后的分流

确认保存成功后：

- 先把确认数据落到本地记录
- 文档状态进入 `待创建`
- 再弹窗询问：
  - `直接上传`
  - `稍后处理`

对应行为：

- `直接上传`
  - 将当前这批已确认且可执行的文档加入后台执行队列
- `稍后处理`
  - 只保存，不入队
  - 文档保持 `待创建`

## 校验与重复检查

### 1. 必填约束

除 `具体产品` 和 `标准版本` 外，其余字段视为必填。

确认保存前必须校验：

文档级必填：

- `标准`
- `归属文件夹`
- `产品类别`
- `PlanSR`
- `条款版本`

条款级必填：

- `条款编号`
- `测试内容`

### 2. 重复检查触发时机

不做编辑过程中的实时重复检查，只在以下两个时机统一检查：

- `保存确认` 前
- `开始执行` 前

### 3. 重复判定规则

同一个 `folder.id` 下，若：

- `term` 相同
- `testContent` 相同

则标记为“可能已存在”。

### 4. 用户决策

对于每条疑似重复条款，用户可以选择：

- `仍然创建`
- `跳过此条`

要求：

- 逐条决策
- 不影响同文档其他条款
- 不影响其他文档

被跳过的条款状态记为 `用户跳过`，且后续允许恢复。

## 状态模型

### 1. 文档级状态

- `待拆分`
- `拆分中`
- `待确认`
- `待创建`
- `创建中`
- `待上传`
- `上传中`
- `已完成`
- `部分完成`
- `已跳过`
- `失败`

### 2. 条款级状态

- `待创建`
- `创建失败`
- `待上传`
- `上传成功`
- `上传失败`
- `用户跳过`

### 3. 可执行的文档状态

以下文档状态视为“可执行”：

- `待创建`
- `待上传`
- `部分完成`
- `失败`

以下文档状态默认不可执行：

- `待确认`
- `创建中`
- `上传中`
- `已完成`
- `已跳过`

当用户一次选中多个文档点击“开始执行”时：

- 只把可执行文档加入队列
- 不可执行文档不阻断整体
- 需要提示哪些文档被跳过以及原因

## 后台执行器设计

### 1. 执行模型

- 文档级串行执行
- 单个文档内部按拆分出的原始顺序处理条款
- 采用两阶段处理：
  1. 批量创建条款
  2. 批量上传 docx

### 2. 第一阶段：创建

对某个文档下的条款按顺序遍历：

- 仅处理 `待创建`
- `用户跳过` 不处理
- 已有 `chapter_id` 的条款不重复创建

创建成功后：

- 回填 `chapter_id`
- 条款状态改为 `待上传`

创建失败后：

- 条款状态改为 `创建失败`
- 保存后端错误信息

### 3. 第二阶段：上传

对某个文档下的条款按顺序遍历：

- 仅处理 `待上传`
- 使用原拆分得到的本地 docx 文件
- 调用 `POST /api/chapter-doc/import`

上传成功后：

- 条款状态改为 `上传成功`

上传失败后：

- 条款状态改为 `上传失败`
- 保存后端错误信息

### 4. 从当前状态继续

再次点击“开始执行”时，不从头重跑，而是自动续跑：

- `待创建` -> 继续创建
- `待上传` -> 继续上传
- `创建失败` -> 不自动重试，需用户手动处理
- `上传失败` -> 不自动重试，需用户手动处理
- `上传成功` / `用户跳过` -> 永远跳过

## 取消与删除规则

### 1. 取消入口

- 取消不做批量按钮
- 取消入口位于右键菜单

### 2. 取消语义

- 支持取消当前执行队列
- 不是强杀
- 只在安全点生效

安全点定义：

- 当前创建请求结束后
- 或当前上传请求结束后

取消后：

- 已成功/失败的条款保持原状态
- 尚未处理到的条款保持原待处理状态，不改成跳过或取消

文档聚合状态规则：

- 如果取消发生在创建阶段，且当前文档已出现 `待上传` 条款，但尚未开始任何上传尝试，则文档状态保持为 `待上传`
- 如果取消前已有部分或全部条款上传成功，则文档状态记为 `部分完成`
- 如果取消前没有任何条款上传成功，且已尝试上传的全部失败，则文档状态记为 `失败`

### 3. 删除语义

- 只删除这个模块的本地记录
- 不删除本地原始文件
- 不删除后端已创建的 Chapter
- 不删除已上传文档

### 4. 删除前置约束

- 只要文档仍在执行队列里，不论等待执行还是正在执行，都不能删除
- 用户必须先取消该执行流程
- 取消生效后，文档脱离队列，才允许删除本地记录

## 结果与失败恢复

### 1. 工作台即结果页

结果页不是一次性报表，而是主工作台本身。

- 每个文档行展示聚合结果
- 双击打开抽屉查看条款级明细
- 失败、待上传、部分完成、跳过项会长期保留
- 重启应用后仍可继续处理

### 2. 条款级恢复能力

创建失败条款：

- 可编辑本地字段
- 可重试创建

上传失败条款：

- 可编辑本地字段
- 可重试上传

跳过条款：

- 可恢复到处理流程

### 3. 已创建成功条款的手动同步

前后端支持编辑条款，但此模块进行如下约束：

- 只有后端**草稿状态**的条款允许编辑并手动同步
- 不自动同步
- 用户必须显式执行“同步到后端”
- 同步粒度仅为**条款级**

### 4. 条款级操作

结果页中条款级至少支持：

- `重试创建`
- `重试上传`
- `同步到后端`
- `打开本地 docx`
- `打开后端 chapter 记录`
- `恢复跳过`

### 5. 后端 Chapter 记录定位

结果页中需要同时支持：

- 显示 `chapter ID`
- 在 `tuv-tools` 内直接打开并定位到现有条款管理页中的对应记录

首版暂不支持直接打开 OnlyOffice 在线文档。

## 风险与约束

- 目录树命名可能不完全标准化，因此“标准号目录唯一命中”不能假定总是成立
- 创建与上传是两个阶段，天然存在“部分成功”状态
- 编辑字段与 docx 内容解耦，需在界面上向用户明确说明
- 重新拆分只重置本地记录，不回收历史后端对象，结果页文案必须清楚

## 验收标准

- 用户可以在一个独立页面中完成“导入、拆分、确认、创建、上传、恢复”的完整流程
- 文档在工作台中独立持久化管理
- 批量导入后统一选择拆分模式并自动拆分
- 后续可对单个文档重新拆分
- 双击文档后从右侧滑出抽屉
- 多文档确认时抽屉顶部按当前列表顺序显示标签页
- 列表长期显示模式值为 `章节` / `条款`
- 确认后可选择“直接上传”或“稍后处理”
- 后台按文档级串行执行
- 可执行状态仅包括：
  - `待创建`
  - `待上传`
  - `部分完成`
  - `失败`
- 条款级失败项可编辑、可重试
- 结果页同时支持显示 `chapter ID` 和打开后端 chapter 记录

## 需在实现前保持不变的假设

- 条款目录树根节点继续使用 `id = 2`
- `POST /api/chapter-doc/import` 在目标环境可用，且协议与 `feature/chapter-doc-import` 分支一致
- `folder.id` 仍是新增条款时的合法归属字段
- 本地拆分结果能够稳定得到每条条款对应的输出 docx 路径
